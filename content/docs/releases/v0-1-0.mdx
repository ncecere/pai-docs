This page is the record of the first release. What has changed since is in [v0.2.0](/docs/releases/v0-2-0).

The first release: a chat app for [Pi Durable](https://github.com/ncecere/pi-durable-platform) agents, where every person who signs in gets their own assistant, built from the Open Chat Interface web app.

## Chat

- Streaming conversations with an agent: reasoning, tool steps (what each tool acted on, its inputs and live output) and Markdown, with syntax highlighting, tables, maths and diagrams.
- Messages sent while the agent is working queue behind the current reply; Stop works; sends are safe to retry.
- A conversation follows the platform's stream and reconnects on its own; a background tab lets an idle agent sleep.

## Inbox

- One list of every conversation: **Pinned**, **Working** and **Inbox**, with **Snoozed**, **Done** and **Archived** shelves.
- A reply that finishes or fails while you are elsewhere shows as **New reply** or **Failed**, and the tab title counts them. Snoozes end early when the agent finishes; done conversations return on new activity.
- Replies still being written when you leave a conversation are followed, so they are noticed when they finish.
- Hover actions and a menu with everything (always shown on touch screens); Undo for every change but Delete.

## Agents

- Animated avatars (Face, Signal, Pixel) that show what the agent is doing: idle, thinking, working, waiting, needs you, done, error, asleep. Chosen per browser in the Appearance menu.

## Accounts and security

- People sign in to the app with single sign-on (OpenID Connect), never to the agent platform. A small server holds the platform team's service account key and relays each person's own agent routes only.
- Encrypted cookie sessions, a CSRF token and an `Origin` check on writes, an ownership check on every agent request, a cap on open streams per person, a strict Content Security Policy, and HSTS over https.
- Development accounts (Tim, Bob and Sally) with `DEV_AUTH=true`, loopback only.

## Deployment

- `docker build .`: one Node.js process serves the web app and the API, runs as a non-root user, with a health check on `/healthz`.

## Known limitations

- Inbox state is kept in the browser (per person, cleared on sign-out); it doesn't follow you between devices.
- "Working" and "New reply" are known only for conversations this browser has seen working. A reply that finishes while the app is closed isn't flagged.
- One assistant per person.
- No attachments, tool approvals, message editing or branching, or search of message text.
- Single sign-on is tested against an in-process provider, not against a particular identity provider.
- No access control by identity-provider group.
- The icons and the sidebar mark were Open Chat Interface's, to be replaced.

Several of these are addressed in [v0.2.0](/docs/releases/v0-2-0).
