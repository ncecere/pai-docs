## Before 1.0

- **It is development software.** It is tested with unit tests and server tests against a real PostgreSQL and an in-process OpenID Connect provider. Since v0.4.0 CI also runs **browser tests** (`pnpm e2e`) in a real browser, on a desktop and a phone-sized touch screen, against a fake agent platform: sign-in, chat with a streamed reply, the inbox, administration access and the Connect flow, plus the [accessibility checks](/docs/use/accessibility). The browser tests are not part of the shipped image. To run them, you need the product repository, a PostgreSQL (`pnpm db:up` starts one for development, or set `TEST_DATABASE_URL`) and, the first time, `pnpm exec playwright install chromium`; then `pnpm build && pnpm e2e`. Try it in your environment before you rely on it.
- **Upgrades only go forward.** Migrations can't be undone by changing images; going back past one means restoring a backup. Read every release's notes between your version and the target. See [Upgrades and backups](/docs/operate/upgrades-and-backups).
- **The app's HTTP API isn't a public contract.** It serves the app's own web app and may change in any release.

## How releases are published

Each release is a Git tag, `vX.Y.Z`, whose version matches `package.json` and whose notes are the `## X.Y.Z` section of `CHANGELOG.md`. Pushing the tag runs the repository's `image.yml` workflow, which builds the image for linux/amd64 and linux/arm64, checks that it reports the version and runs as the non-root user, scans it, publishes `ghcr.io/ncecere/pi-agent-interface:vX.Y.Z` (and `latest` for final releases), signs it with cosign keyless signing, and creates the GitHub release with the image's digest. The workflow was added after v0.1.0, so v0.1.0 has no published image and v0.2.0 is the first that has (v0.5.1 is the latest). See [The container image](/docs/operate/container#getting-the-image).
