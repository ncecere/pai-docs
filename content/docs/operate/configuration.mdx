title: Configuration
description: Every Pi Agent Interface environment variable, its default, and exactly how the server checks it when it starts.
---

Pi Agent Interface reads its configuration from environment variables once, when it starts. Everything else (the default model, provided agents, branding, optional features) is set by administrators in the [admin dashboard](/docs/administer) and stored in PostgreSQL.

## How settings are read

- **Environment variables.** In development, the server also reads `.env.local` and then `.env` from its working directory, when they exist; a real environment variable wins over both. The container image ignores these files when it is built (`.dockerignore`), so pass settings to the container as environment variables.
- **Values are trimmed**: surrounding spaces are ignored, and a value of only spaces counts as empty.
- **Every problem at once.** If anything is missing or unsafe, the server doesn't start, and prints every problem:

  ```text
  Error: Configuration:
    - SESSION_SECRET must be at least 32 characters
    - DATABASE_URL is required
    - APP_URL must use https outside local development
  ```

A **loopback** address below means a URL whose host is `localhost`, `127.0.0.1` or `[::1]`.

## The app

| Variable | Default | Checked |
|---|---|---|
| `APP_URL` | `http://localhost:5177` | Where people open the app, for example `https://chat.example.com`. Must be a URL ("APP_URL is not a URL"), and https unless it is loopback ("APP_URL must use https outside local development"). Its origin is the only one allowed to write; the sign-in redirect is `<APP_URL>/auth/callback`. Keep it equal to the public address. |
| `HOST` | `127.0.0.1` | The address to listen on. The container image sets `0.0.0.0`. Not checked. |
| `PORT` | `5178` | The port to listen on. The container image sets `8080`. Not checked: use a port number. |
| `STATIC_DIR` | none | Serves the built web app from this directory, with every other path answered by its `index.html`. The container image sets `/app/dist`; `pnpm start` uses `dist`. Without it, the server serves only the API (development, where Vite serves the web app). |
| `APP_NAME` | none | The app's name until an administrator saves [Branding](/docs/administer/branding); then Branding's name wins. Empty: **Pi Agent Interface**. Not checked. |

## The agent platform

See [The agent platform](/docs/operate/platform) for the two modes and what to set up on the platform.

| Variable | Default | Checked |
|---|---|---|
| `PLATFORM_URL` | none (required) | The platform's address, for example `https://agents.example.com`. Must be a URL, and https unless it is loopback ("PLATFORM_URL must use https (the service key travels with every request)"; the message is the same in Connect mode, where people's tokens travel instead). |
| `PLATFORM_AUTH` | `service` if `PLATFORM_SERVICE_KEY` is set, else `connect` | How the app reaches people's agents. **`connect`**: each person connects their own platform account, and their agents live in their personal workspace. **`service`**: one team service account, for a platform without Connect. Anything else: "PLATFORM_AUTH is connect or service". A deployment from v0.1.0 that has a service key stays in service mode. |
| `CONNECT_EMAIL_MATCH` | `require` | Connect mode only. `require` refuses a platform account whose email differs from the person's email here (see [the account check](/docs/operate/security#the-account-check-connect-mode)); `off` skips the check, for deployments whose app and platform use different identity providers. Anything else: "CONNECT_EMAIL_MATCH is require or off". |
| `PLATFORM_TEAM` | none | **Service mode only**: the team's slug, for example `pi-agent-interface`. Required there ("PLATFORM_TEAM is required"); its value isn't checked until the first call. Not used in Connect mode, where it needs no value. |
| `PLATFORM_SERVICE_KEY` (secret) | none | **Service mode only**: the team service account's key, `pdp_sa_…`, role editor. Required there; never sent to browsers. A wrong key shows up at the first call, as "The agent platform refused this app's service key." Setting it without `PLATFORM_AUTH` selects service mode. Not used in Connect mode. |
| `AGENT_TEMPLATE` | empty | The slug of the platform template the built-in assistant (and any provided agent left on **The default template**) is made from. Empty: the platform's default. In Connect mode it is looked up in the platform's catalog, and a slug that isn't there leaves the agent on the platform's default template. Not checked at start. |
| `AGENT_NAME` | `Assistant` | The built-in assistant's name until an administrator renames it in Admin → Agents. |
| `AGENT_MODEL` | empty | The default model, by name or id, until an administrator picks one in Admin → Agents (which wins). Only a model currently published to the team (in Connect mode, one the person's personal workspace may use) and enabled is ever set; if it isn't one, agents are left on their model and the log says so once. Empty: the platform decides (the template's model, then its default). |

## Sign-in

At least one way to sign in is required: OIDC, or `DEV_AUTH` on a loopback `APP_URL` ("Configure OIDC_* for sign-in (or DEV_AUTH=true locally)"). See [Sign-in](/docs/operate/sign-in).

| Variable | Default | Checked |
|---|---|---|
| `OIDC_ISSUER` | none | Your identity provider's issuer URL. Must be a URL, and https unless it is loopback ("OIDC_ISSUER must use https"). Discovery happens at the first sign-in, so a wrong issuer shows up then, in the log. |
| `OIDC_CLIENT_ID` | none | The client's ID. |
| `OIDC_CLIENT_SECRET` (secret) | none | The client's secret. The three `OIDC_*` above go together: any one set without the others stops the server ("OIDC_ISSUER, OIDC_CLIENT_ID and OIDC_CLIENT_SECRET go together"). |
| `OIDC_SCOPES` | `openid profile email` | The scopes asked for, separated by spaces. Used only with OIDC. Add one if your provider needs a scope to release the groups claim. |
| `OIDC_ALLOWED_GROUPS` | empty | Comma-separated group names. When set, only members of one of these (or of an admin group) can sign in. Everyone else sees "Your account isn't allowed to use this app. Ask an administrator to add you to its group." and, if they had signed in before, their sessions end. Empty: anyone your provider signs in. Needs OIDC ("OIDC_ALLOWED_GROUPS and OIDC_ADMIN_GROUPS need single sign-on (OIDC_*)"). |
| `OIDC_ADMIN_GROUPS` | empty | Comma-separated group names. When set, the provider decides who is an administrator, on every sign-in: members become administrators, others members, and Admin → People can't change roles. The last active administrator is never demoted this way. Empty: administrators are set in the app. Needs OIDC. |
| `OIDC_GROUPS_CLAIM` | `groups` | Where the provider lists a person's groups: the claim's name, or a dotted path for a nested one (`realm_access.roles`). Looked for in the ID token, then at the userinfo endpoint. Names are matched exactly. Only read when one of the two group lists is set. |
| `DEV_AUTH` | `false` | Exactly `true` turns on the development accounts Tim, Bob and Sally (`tim@example.test` and so on), with no password. Refused unless `APP_URL` is loopback ("DEV_AUTH requires a loopback APP_URL"). Any other value is off. |
| `DEV_ACCOUNTS` | the three accounts above | Development only. With `DEV_AUTH=true`, a JSON array of `{"id","name","email"}` that replaces Tim, Bob and Sally, for example `[{"id":"priya","name":"Priya Shah","email":"priya.shah@example.com"}]`. Each `id` is unique, 1 to 64 letters, digits, dots, dashes or underscores; `name` and `email` are required, and there must be at least one account. An invalid value stops the server and names the problem. Ignored while `DEV_AUTH` is off. |

## Sessions

| Variable | Default | Checked |
|---|---|---|
| `SESSION_SECRET` (secret) | none (required) | At least 32 characters ("SESSION_SECRET must be at least 32 characters"); generate one with `openssl rand -base64 48`. Encrypts session cookies and, in Connect mode, the platform tokens the app keeps for people. Changing it alone signs everyone out, and in Connect mode everyone has to connect again, since the stored tokens can't be read any more; to replace it without that, [rotate it](/docs/operate/rotating-the-session-secret). |
| `SESSION_SECRET_PREVIOUS` (secret) | empty | Secrets this deployment used before, comma-separated, still accepted for opening sessions and stored platform tokens during a [rotation](/docs/operate/rotating-the-session-secret). New values are always sealed with `SESSION_SECRET`. Every one must be at least 32 characters ("SESSION_SECRET_PREVIOUS: every secret must be at least 32 characters"); a value equal to `SESSION_SECRET` is ignored. Empty normally. |
| `SESSION_TTL_HOURS` | `168` (7 days) | How long a session lasts, in hours. A value that isn't a positive number is silently replaced by 168. A session isn't extended by use: people sign in again when it ends. |

## Database and administration

| Variable | Default | Checked |
|---|---|---|
| `DATABASE_URL` (secret) | none (required) | The app's own PostgreSQL, for example `postgres://pai:…@db.example.com:5432/pai`. Required; a wrong one fails when the server connects, before it listens. Migrated on start. See [PostgreSQL and migrations](/docs/operate/database). |
| `INITIAL_ADMIN_EMAIL` | none | Becomes an administrator on signing in, while there is no active administrator. See [The first administrator](/docs/administer/first-administrator). |
| `DISABLED_FEATURES` | empty | Optional features to turn off for good, comma-separated: `usage`, `myUsage` (case-sensitive). An unknown name stops the server (`DISABLED_FEATURES: there is no feature "…" (known: usage, myUsage)`). In Connect mode `usage` is off whatever this says. See [Features](/docs/administer/features). |

## Metrics

Off unless `METRICS_ENABLED` is `true`. See [Metrics](/docs/operate/metrics).

| Variable | Default | Checked |
|---|---|---|
| `METRICS_ENABLED` | `false` | Exactly `true` serves Prometheus metrics on a port of their own. Any other value is off. |
| `METRICS_PORT` | `9464` | The port the metrics listen on. Must be a port number ("METRICS_PORT is a port number") and different from `PORT` ("METRICS_PORT must differ from PORT"). Only checked while metrics are on. |
| `METRICS_HOST` | `0.0.0.0` | The address the metrics listen on. Never publish this port outside your cluster or monitoring network. |

## Set by the image

The container image sets `NODE_ENV=production`, `HOST=0.0.0.0`, `PORT=8080` and `STATIC_DIR=/app/dist`. Override them only if you have a reason to.

## A production example

In Connect mode, the default, there is no team or key to set:

```sh title="pai.env"
APP_URL=https://chat.example.com
PLATFORM_URL=https://agents.example.com
PLATFORM_AUTH=connect
DATABASE_URL=postgres://pai:...@db.example.com:5432/pai
SESSION_SECRET=...            # openssl rand -base64 48
OIDC_ISSUER=https://sso.example.com/application/o/pai/
OIDC_CLIENT_ID=pi-agent-interface
OIDC_CLIENT_SECRET=...
INITIAL_ADMIN_EMAIL=morgan.lee@example.com
```

To limit sign-in and choose administrators by the provider's groups, add `OIDC_ALLOWED_GROUPS=chat-users` and `OIDC_ADMIN_GROUPS=chat-admins` (see [Sign-in](/docs/operate/sign-in#access-and-administrators-by-group)).

For a platform without Connect, with a team service account:

```sh title="pai.env"
APP_URL=https://chat.example.com
PLATFORM_URL=https://agents.example.com
PLATFORM_AUTH=service
PLATFORM_TEAM=pi-agent-interface
PLATFORM_SERVICE_KEY=pdp_sa_...
AGENT_MODEL=Chat model
DATABASE_URL=postgres://pai:...@db.example.com:5432/pai
SESSION_SECRET=...            # openssl rand -base64 48
OIDC_ISSUER=https://sso.example.com/application/o/pai/
OIDC_CLIENT_ID=pi-agent-interface
OIDC_CLIENT_SECRET=...
INITIAL_ADMIN_EMAIL=morgan.lee@example.com
```

In Connect mode the platform fetches `<APP_URL>/oauth/client-metadata.json` from the app's public address, so that path must be reachable without sign-in. See [The agent platform](/docs/operate/platform#the-client-id-metadata-document). For local development with Connect, add `CONNECT_EMAIL_MATCH=off` if your development accounts' emails aren't your platform account's.
