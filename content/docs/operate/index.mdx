description: What it takes to run Pi Agent Interface — a Pi Durable platform (with Connect, or a team service account), an identity provider, PostgreSQL and one container.
---

Pi Agent Interface is one Node.js server, in one container image, that serves the web app and its API. It needs:

| Needs | For | See |
|---|---|---|
| **A Pi Durable platform**: in Connect mode (the default), one that offers Connect and has personal workspaces on; in service mode, a team with an editor service account, its key and a published model | The agents and their conversations | [The agent platform](/docs/operate/platform) |
| **An OpenID Connect provider** with a confidential client | Sign-in | [Sign-in](/docs/operate/sign-in) |
| **PostgreSQL** | People, roles, settings, preferences and the audit log | [PostgreSQL and migrations](/docs/operate/database) |
| **A reverse proxy or ingress** that terminates TLS and doesn't buffer event streams | The public https address | [The container image](/docs/operate/container#behind-a-reverse-proxy) |

The server is configured with environment variables, checked when it starts: an incomplete or unsafe configuration stops it with every problem listed. See [Configuration](/docs/operate/configuration).

```text
browser ──https──▶ reverse proxy ──▶ Pi Agent Interface (:8080) ──https + the person's token──▶ Pi Durable platform
                                        │                                (Connect, the default; a team
                                        │                                 service key in service mode)
                                        └──▶ PostgreSQL

Pi Durable platform ──https──▶ <APP_URL>/oauth/client-metadata.json   (Connect: it must be reachable without sign-in)
```
